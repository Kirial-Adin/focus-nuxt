# Руководство по внесению вклада (Contributing Guide)

Рад, что вы решили помочь в развитии проекта! Чтобы процесс совместной работы был комфортным и эффективным, пожалуйста, следуйте этим простым правилам.

## 🐛 Как сообщить о баге или предложить фичу

Если вы нашли ошибку или у вас есть идея по улучшению:

1. Проверьте существующие [Issues](https://github.com), чтобы убедиться, что эту проблему еще никто не создал.
2. Если проблемы нет, создайте новую, используя шаблон:
   - **Что произошло:** Шаги для воспроизведения бага.
   - **Ожидаемый результат:** Как код должен работать на самом деле.
   - **Скриншоты/Логи:** Если применимо.

## 🛠️ Процесс разработки

1. **Сделайте Fork** репозитория на свой аккаунт.
2. **Клонируйте** ваш форк локально:
   ```bash
   git clone https://github.com
   ```
3. **Создайте новую ветку** от ветки `main`. Имя ветки должно отражать суть изменений:
   - `feat/short-description` — для новых фич.
   - `fix/short-description` — для исправления багов.
   - `docs/short-description` — для изменений в документации.
4. **Установите зависимости** и запустите проект (инструкции по запуску см. в `README.md`).
5. **Внесите изменения** и обязательно протестируйте их.

## 📐 Стандарты оформления и автоматизация

В нашем проекте настроена автоматическая проверка качества кода. Вам не нужно настраивать всё вручную, но важно знать, как это работает.

### 🐶 Проверки перед коммитом (Husky)

В проекте используется **Husky**. При попытке сделать `git commit` автоматически запускаются хуки, которые проверяют ваш код:

- **Линтер и форматирование:** Автоматически прогоняются `eslint` и `prettier`. Если есть ошибки, коммит заблокируется. Исправьте их и попробуйте снова.
- **Имена коммитов:** Мы используем стандарт **Conventional Commits**. Хук проверит, чтобы коммит начинался с правильного тега (например, `feat:`, `fix:`, `docs:`, `chore:`).

> 💡 **Пример правильного коммита:** `git commit -m "feat: добавлен хук авторизации"`

## 🚀 Как отправить Pull Request (PR)

1. Перед отправкой убедитесь, что локально всё собирается и проходит тесты:
   ```bash
   pnpm run lint   # Проверить стиль кода
   pnpm run test   # Запустить локальные тесты (если есть)
   ```
2. Отправьте изменения в свой форк и создайте Pull Request в ветку `main` оригинального проекта.
3. В описании PR обязательно укажите, какую задачу или Issue вы решаете (например: `Исправляет #12`).

### 🤖 Проверка в GitHub Actions (CI)

Как только вы создадите или обновите Pull Request, автоматически запустится наш **CI/CD пайплайн в GitHub Actions**:

- Он развернет проект в чистой среде, установит зависимости и запустит тесты.
- **Важно:** Pull Request не может быть влит (merged) в ветку `main`, если проверки GitHub Actions завершились ошибкой (горит красный маркер).
- Если тесты упали, исправьте ошибки локально, сделайте новый коммит и запушьте — GitHub Actions автоматически перепроверит код.
